## A. ROOT CAUSE of !G1002 (src/museum/museum.nas + shell.nas): pc in the trap is HEX: 0x1002 = SLOT(4096)+2.
 shell key '1' does BCOPY dst=4096 src=baby_store len=341, then JMP 4096. But baby_store (word 3072) holds a single '.word 0'
 and the image ends at word 3072 (3073 words); the rest is never-loaded zero memory = illegal heads = gate trap on first fetch.
 => The cartridge was never packed: the 'TOC filled by build script' step does not exist. It is NOT a kernel bug and NOT a bad opcode.
 Other draft defects found: baby_store and baby_len share word 3072; lib_bcopy comment says r1=src,r2=dst but the instruction is
 BCOPY d=dst,a=src,b=count (shell passes it correctly, the comment is wrong); src/museum/baby.nas (monolith) uses @vcls/@vputs labels and
 'JMP @menu' as exit, so it cannot run as a cartridge until retargeted to vector calls (CALL #V_PUTS) and 'RET' (r15 saved at entry,
 because every lib call clobbers r15).
